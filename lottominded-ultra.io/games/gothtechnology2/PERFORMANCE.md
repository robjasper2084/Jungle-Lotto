# Performance implementation

Static HTML contains the catalog and headings. Cormorant Garamond and Share Tech Mono are hosted locally. WebP variants are prepared from preserved sources. The new hero has a 960px source and a larger source. Product cards share one six-cell image atlas; fashion portals share one portrait atlas. Stable media dimensions reserve layout space.

Three.js is a lazy optional atmosphere, not part of the initial store interaction module. Reduced motion and save-data avoid loading it. Rendering stops when the page, hero or active dialog makes the effect unnecessary. The governor lowers device pixel ratio and scene work after persistently poor frame times. The build still reports a greater-than-500KB lazy Three chunk; this warning is not claimed resolved.

No homepage game engine, motion atlases, MP4 or MP3 should be requested. The game and product model code load only after the corresponding action. The supplied video is a silent H.264 web derivative with fast-start metadata and no autoplay audio.

Browser QA records LCP, CLS, DOMContentLoaded and resources in each visual test's performance.json under output/store-browser. These are local, unthrottled laboratory samples, not production Core Web Vitals or a Lighthouse score. Re-measure a real deployed page on constrained Android hardware before claiming field performance.

Optional GLB models, bloom effects, full multi-scene 3D showroom geometry and external commerce latency are not exercised without production assets/configuration. The current hero is artwork with a subtle optional 3D atmosphere. Product fallback is an honestly labeled 2.5D image display.
